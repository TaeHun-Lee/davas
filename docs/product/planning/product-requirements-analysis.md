# Davas 제품 요구사항 상세 설계

> 문서 역할: TO-BE 제품 요구사항
>
> 기준 문서: [Davas 제품 기준 문서](../README.md)
>
> 우선순위: 내용이 충돌하면 기준 문서를 우선한다.

## 1. 목적과 범위

Davas는 가까운 사람들이 영화와 드라마 감상을 각자 기록하고, 선택한 공유 공간에서 서로의 감상과 평가를 확인하며, 다음에 함께 볼 작품을 고르는 비공개 서비스다.

초기 실제 사용자는 연인 두 명이지만 제품과 데이터 모델은 다음을 전제로 한다.

- 하나의 공유 공간에는 활성 구성원이 2~5명까지 참여한다.
- 공간 생성 직후에는 소유자 한 명만 있어도 된다.
- 한 사용자는 장기적으로 여러 공간에 참여할 수 있다.
- 개인 기록이 원본이며 공유 공간은 공개 범위를 결정하는 경계다.
- 친구, 6명 이상 그룹, 공개 소셜 기능은 확장 가능성만 보존하고 MVP에는 넣지 않는다.

## 2. 제품 원칙

1. 기록의 소유자는 작성자다.
2. 함께 본 작품이라도 별점과 리뷰는 각자 작성한다.
3. 공유 여부와 공유 대상은 기록마다 분명해야 한다.
4. 공간에 가입했다고 과거 개인 기록이 자동으로 공유되지 않는다.
5. 한 사람의 입력만으로 다른 사람의 감상 사실이나 평가를 확정하지 않는다.
6. 추천은 인기보다 지금 볼 수 있는지와 참여자별 최소 만족도를 우선한다.
7. 입력 부담을 낮추되 데이터 의미를 모호하게 만들지 않는다.

## 3. 사용자와 관계 모델

### 사용자

- 계정, 로그인 수단, 표시 이름, 프로필을 가진다.
- 작품별 별점, 리뷰, 관심, 비선호와 감상 기록을 소유한다.
- 기본 지역, 사용하는 OTT, 알림 설정을 관리한다.

### 공유 공간

- 2~5명이 기록과 추천을 공유하는 비공개 경계다.
- 소유자와 일반 구성원을 구분한다.
- 초대 수락 전에는 공간 데이터에 접근할 수 없다.
- 한 구성원의 탈퇴가 나머지 구성원의 감상 사실을 삭제하지 않는다.

### 감상 참여자

- 감상 기록의 작성자가 다른 구성원을 참여자로 초대할 수 있다.
- 초대된 사용자는 `pending`, `confirmed`, `declined` 중 하나의 상태를 가진다.
- 확인한 사용자만 자신의 별점과 리뷰를 같은 감상 건에 연결한다.

## 4. 핵심 사용자 흐름

### 4.1 공간 시작

1. 사용자가 가입하고 프로필을 만든다.
2. 공유 공간을 생성하고 만료되는 초대 링크를 발급한다.
3. 상대가 공간과 초대자를 확인한 뒤 수락한다.
4. 각 구성원이 지역, OTT 서비스, 기본 공유 범위를 설정한다.
5. 공간은 최대 5명까지 같은 방식으로 확장된다.

### 4.2 감상 기록

1. 사용자가 영화 또는 드라마를 검색한다.
2. 감상일을 입력한다.
3. 별점, 리뷰, 극장·OTT·기타 시청 방식, 장소, 함께 본 사람을 선택한다.
4. 개인 보관 또는 하나 이상의 허용된 공유 공간을 선택한다.
5. 함께 본 사람은 참여 요청을 확인하고 자신의 평가를 별도로 남긴다.

작품 하나를 여러 번 볼 수 있으므로 작품과 감상 기록은 일대다가 된다.

### 4.3 공유 감상 확인

1. 공간 타임라인에서 최근 감상 기록을 본다.
2. 작품 상세에서 구성원별 별점과 리뷰를 나란히 본다.
3. 참여 확인 전인 사용자의 평가나 관심사는 노출하지 않는다.
4. 기록을 수정하면 허용된 구성원에게 최신 상태가 반영된다.

### 4.4 함께 볼 작품 선택

1. 공간 구성원 중 이번 추천 참여자를 고른다.
2. 지역, OTT, 콘텐츠 유형, 시간, 분위기와 제외 조건을 입력한다.
3. 시스템이 실제 시청 가능한 작품만 우선 후보로 만든다.
4. 참여자별 만족도와 그룹 균형을 반영해 이유와 함께 순위를 제공한다.
5. 참여자가 관심 또는 거절을 표시하고 합의 규칙을 충족하면 선택을 마친다.
6. 감상 후 각자의 평가가 다음 추천에 반영된다.

## 5. 기능 요구사항

### 5.1 계정과 인증

- 이메일 또는 검증된 외부 로그인 수단으로 가입하고 로그인한다.
- 세션 종료, 비밀번호 또는 로그인 수단 복구를 지원한다.
- 표시 이름과 프로필 이미지를 변경할 수 있다.
- 계정 데이터 내보내기와 삭제를 요청할 수 있다.

### 5.2 공간과 초대

- 사용자는 공간을 생성하고 이름을 변경할 수 있다.
- 초대 링크는 일회성 또는 제한된 사용 횟수와 만료 시각을 가진다.
- 만료, 취소, 이미 사용됨, 정원 초과를 구분한다.
- 마지막 소유자는 소유권을 이전하거나 공간 종료를 선택해야 탈퇴할 수 있다.
- 정원 확인과 가입은 하나의 원자적 처리로 수행한다.
- MVP UI는 한 개의 활성 공간에 집중하되 스키마는 복수 공간을 허용한다.

### 5.3 작품 카탈로그

- 영화와 드라마를 제목, 원제, 인물 등 지원 가능한 조건으로 검색한다.
- 외부 공급자의 작품 ID를 내부 정규 작품 ID에 연결한다.
- 작품 상세에는 유형, 개봉·공개 상태, 장르, 상영 시간, 이미지와 출처를 표시한다.
- 외부 공급자 실패 시 기존 기록의 제목과 사용자의 리뷰는 계속 조회할 수 있어야 한다.

### 5.4 감상 기록과 평가

- 필수 입력은 작품과 감상일이다.
- 별점은 미평가 또는 0.5~5.0의 0.5 단위다.
- 리뷰, 감상 시각, 장소 텍스트, 시청 방식, OTT·극장, 참여자는 선택 사항이다.
- 장소는 자유 텍스트로 저장하며 GPS 좌표를 자동 수집하지 않는다.
- 드라마는 MVP에서 작품 단위로 기록하고 에피소드 진도는 제외한다.
- 작성자는 자신의 기록, 별점, 리뷰를 수정하거나 삭제할 수 있다.
- 공동 감상의 사실과 각 개인의 반응은 별도 데이터로 유지한다.

### 5.5 공유와 조회

- 기록 저장 전에 개인 보관과 공유 공간을 명확히 보여준다.
- 공유 공간 타임라인은 최신순 커서 페이지네이션을 지원한다.
- 동일 작품의 구성원별 반응을 비교할 수 있다.
- 새 공간 가입 시 기존 개인 기록을 자동 공개하지 않는다.
- 탈퇴 즉시 해당 공간의 비공개 데이터 접근을 차단한다.
- 권한 없는 리소스는 존재 여부가 드러나지 않게 응답한다.

### 5.6 추천

- 추천 요청마다 2~5명의 참여자와 조건을 선택한다.
- 참여자가 명시적으로 싫다고 한 작품과 이미 본 작품은 기본 제외한다.
- OTT·지역·공개 상태를 하드 필터로 먼저 적용한다.
- 데이터가 적은 사용자를 비선호로 간주하지 않는다.
- 결과에는 검증 가능한 추천 이유와 시청 가능 경로를 표시한다.
- 관심, 관심 없음, 이미 봄, 시청 가능 정보 오류를 피드백으로 받는다.
- 세부 점수와 단계적 고도화는 [추천 전략](recommendation-strategy-analysis.md)을 따른다.

### 5.7 알림

- 초대, 감상 참여 요청, 필수 관계 변경은 기본 알림 대상이다.
- 새 리뷰나 추천 관련 알림은 사용자가 켜고 끌 수 있다.
- 동일 이벤트의 중복 발송을 방지한다.
- 알림 본문에 비공개 리뷰 전문이나 숨겨진 선호를 넣지 않는다.

### 5.8 개인정보와 생명주기

- 사용자는 자신이 제공한 데이터를 내보낼 수 있다.
- 계정 삭제에는 복구 유예 기간을 둔다.
- 유예 종료 후 리뷰, 위치 텍스트, 선호 등 개인 데이터는 영구 삭제하거나 비식별화한다.
- 다른 구성원의 감상 사실을 유지하더라도 삭제 사용자의 기여는 노출하지 않는다.
- 백업에도 삭제 정책과 최대 보존 기간을 적용한다.

## 6. 기본 정책

| 항목 | 기본값 |
|---|---|
| 초기 사용 맥락 | 연인 2명 |
| 공간 정원 | 활성 구성원 2~5명 |
| 감상 기록 필수값 | 작품, 감상일 |
| 별점 | 선택, 0.5~5.0 |
| 공유 | 저장 시 명시적으로 확인 |
| 과거 기록 | 새 공간에 자동 공유하지 않음 |
| 공동 감상 | 상대 확인 필요 |
| 드라마 기록 | 작품 단위 |
| 위치 | 자유 텍스트, GPS 미수집 |
| 추천 지역 | 초기에는 대한민국 한 지역 |
| 추천 합의 | 전원 동의, 필요 시 최소 동의 인원 설정 |
| 알림 | 관계·초대 필수, 나머지 선택 |

## 7. 비기능 요구사항

### 보안과 개인정보

- 모든 쓰기와 비공개 읽기에 서버 측 권한 검사를 적용한다.
- 초대와 복구 토큰은 원문이 아닌 해시로 저장한다.
- 전송 구간을 암호화하고 민감 정보는 로그에서 제외한다.
- 차단, 탈퇴, 삭제 직후 캐시와 검색 결과에서도 접근이 차단되어야 한다.

### 신뢰성

- 작품 공급자 장애가 개인 기록 쓰기와 조회를 막지 않아야 한다.
- 비동기 작업은 재시도해도 한 번만 반영되는 결과를 보장한다.
- 추천 결과에는 가용성 관측 시각과 신뢰도를 남긴다.

### 성능과 접근성

- 일반 기록 조회와 저장은 모바일 환경에서 체감 지연이 작아야 한다.
- 목록은 무제한 로드하지 않고 커서 페이지네이션을 사용한다.
- 키보드 조작, 명확한 레이블, 충분한 색 대비를 제공한다.

## 8. MVP 경계

### 포함

- 계정과 비공개 공유 공간
- 2~5명 초대·가입·탈퇴
- 영화·드라마 검색과 감상 기록
- 개인별 별점과 리뷰
- 날짜, 장소, 극장·OTT 등 시청 방식
- 공유 타임라인과 작품별 평가 비교
- OTT·공개 상태 기반 그룹 추천
- 기본 알림과 개인정보 삭제 흐름

### 제외

- 공개 피드, 팔로우, 댓글, 채팅
- 6명 이상 그룹과 복잡한 관리자 역할
- 에피소드별 진도와 회차별 리뷰
- OTT 결제, 영화표 구매, 영상 재생
- GPS 자동 수집
- 대규모 협업 필터링과 광고 개인화
- 고급 통계, 외부 서비스 기록 일괄 가져오기

## 9. 예외 상황

- 마지막 자리의 초대를 두 명이 동시에 수락하면 한 명만 성공해야 한다.
- 참여 요청을 거절해도 작성자의 감상 기록은 유지된다.
- 기록 공유 후 탈퇴하면 탈퇴자의 개인 반응은 즉시 숨긴다.
- 작품 공급자가 중복 작품을 반환해도 내부 정규 작품은 하나여야 한다.
- OTT 정보가 만료됐거나 공급자 조회가 실패하면 추천 이유에서 확정적으로 표현하지 않는다.
- 한 명의 취향 데이터가 없어도 나머지 사용자 평균으로 덮어쓰지 않는다.
- 모든 후보가 하드 필터에서 제외되면 필터 완화를 임의 적용하지 않고 변경 가능한 조건을 안내한다.

## 10. 성공 지표

핵심 지표는 주간 단위로 구성원 두 명 이상이 서로의 기록 또는 추천에 의미 있게 참여한 활성 공간 수다.

보조 지표:

- 초대 발급부터 두 번째 구성원 활성화까지의 전환율
- 공간별 주간 감상 기록 수와 구성원별 편중도
- 기록 시작부터 저장까지 걸린 시간과 이탈률
- 공유 기록 열람과 개인 반응 작성 비율
- 추천 노출 대비 관심, 합의, 실제 감상 전환율
- 추천 참여자 중 최저 예측 만족도와 감상 후 최저 평가
- OTT·공개 상태 오류 신고율
- 4주 및 8주 공간 유지율

## 11. 분석 이벤트 최소 집합

- `space_created`, `invite_issued`, `invite_accepted`
- `watch_record_started`, `watch_record_saved`, `watch_participation_confirmed`
- `reaction_saved`, `shared_timeline_viewed`
- `recommendation_requested`, `recommendation_exposed`
- `recommendation_feedback_submitted`, `recommendation_selected`
- `availability_error_reported`
- `space_left`, `account_deletion_requested`

분석 이벤트에는 리뷰 전문, 위치 텍스트, 숨겨진 개인 선호를 넣지 않는다.

## 12. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 한 사람만 기록함 | 참여 확인과 가벼운 알림으로 상호 입력 유도 |
| 기록 입력이 번거로움 | 작품·날짜 우선 저장, 나머지는 선택 입력 |
| 과거 기록의 의도치 않은 공개 | 새 공간 자동 공유 금지 |
| 추천이 한 사람에게 편향됨 | 평균과 함께 최저 만족도·편차 반영 |
| OTT 정보가 오래됨 | 관측 시각·TTL·오류 피드백 운영 |
| 공급자 종속 | 내부 작품 ID와 공급자 어댑터 분리 |
| 소셜 기능 조기 확장 | 핵심 기록·공유·추천 지표 검증 전 보류 |

## 13. 출시 전 확정할 결정

- 기본 공유 범위를 개인으로 둘지 최근 사용 공간으로 둘지
- 탈퇴 후 공동 감상 기록에 표시할 익명화 수준
- 계정 삭제 복구 유예 기간과 백업 보존 기간
- 대한민국 작품·OTT 가용성 공급자의 이용 조건과 정확도
- 추천 합의의 기본값을 전원 동의로 고정할지 공간 설정으로 노출할지

이 결정들은 제품 기준을 바꾸면 [제품 기준 문서](../README.md)에 먼저 반영하고, 장기 보존이 필요한 기술 결정은 `docs/decisions/`의 ADR로 남긴다.
