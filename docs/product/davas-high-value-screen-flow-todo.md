## 1. 목적과 우선순위 원칙

이 문서는 현재 구현된 17개 화면을 더 넓게 확장하기보다 다음 핵심 여정을 먼저 완성하기 위한 실행 백로그다.

`초대 코드 가입 → 작품 검색 → 감상 기록·같이 본 경험 작성 → 내 기록 회고 → 보고 싶은 목록 관리 → 가까운 친구와 공유·반응`

우선순위는 다음 기준으로 판단한다.

- **P0:** 사용자 신뢰, 개인정보, 첫 기록 작성 또는 핵심 데이터 정확성을 막는 출시 차단 항목
- **P1:** 사용자 가치와 제품 핵심도가 높고 기존 구현을 재사용할 수 있는 화면·플로우
- **P2:** 운영 안정성과 PWA 사용성을 높이지만 핵심 기록 루프 이후 진행할 항목
- 각 항목은 화면만 그리는 것으로 끝내지 않고 API 권한, 상태 설계, 접근성, 테스트까지 완료해야 한다.

- [x] 회원가입 API가 초대 코드 없이 호출되면 거절한다.
- [ ] 초대 코드 사용과 사용자 생성을 하나의 트랜잭션으로 처리한다.
- [x] 가입 성공 후 홈의 빈 화면보다 작품 탐색·첫 기록 온보딩으로 연결한다.
- [x] 소셜 로그인 버튼은 초대 정책과 통합되기 전까지 노출하지 않는다.

**완료 조건**

- [ ] 유효한 초대 코드가 없으면 신규 계정을 생성할 수 없다.
- [ ] 코드 재사용·동시 사용에도 정해진 사용 횟수 정책이 보장된다.
- [ ] 가입 완료 후 첫 기록 플로우로 자연스럽게 이어진다.

### P1-04. 같이 본 경험 작성·수정·회고

대상 화면: `/diary/new`, `/diary/[id]/edit`, `/diary/[id]`

사용자 플로우:

`기록 작성 → 함께 본 순간 입력 → 저장 → 상세에서 추억 카드로 회고`

- [x] companion 모델이 가입 사용자 연결과 자유 입력 이름을 모두 지원하게 한다.
- [x] 기록에 감상 장소, 분위기, 추억 메모를 저장한다.
- [x] 작성 화면에 선택형 `함께 본 순간` 섹션을 추가한다.
- [x] 친구 선택과 자유 입력 사람을 한 화면에서 추가·삭제할 수 있게 한다.
- [x] 장소는 자유 입력을 기본으로 하고 최근 입력 재사용은 후속 개선으로 둔다.
- [x] 분위기는 소수의 칩 선택과 선택적 자유 입력을 지원한다.
- [x] 추억 메모는 본문과 구분된 짧은 개인 회고 필드로 제공한다.
- [ ] 수정 화면에서 기존 입력을 안전하게 불러오고 변경·삭제할 수 있게 한다.
- [x] 상세 화면에는 값이 있을 때만 `함께 본 순간` 카드를 표시한다.
- [x] 공개 범위는 기록 전체를 따르며 companion 이름과 메모만 별도로 노출되지 않게 한다.

**완료 조건**

- [ ] 사람, 장소, 분위기, 추억 메모를 선택적으로 저장·수정·삭제할 수 있다.
- [ ] 계정이 없는 사람도 이름으로 기록할 수 있다.
- [ ] 권한 없는 사용자에게 함께 본 정보가 유출되지 않는다.

### P1-05. 친구 목록·초대·요청 관리

목표 경로: `/friends`

사용자 플로우:

`친구 초대·검색 → 요청 수신 → 수락·거절 → 친구 목록 → 프로필·피드 이동`

- [x] 친구 관계 상태를 `PENDING`, `ACCEPTED`, `REJECTED` 중심으로 정의한다.
- [x] 가입 초대 코드와 친구 초대 코드를 동일 개념으로 쓸지 분리할지 결정한다.
- [ ] 친구 요청 생성·수락·거절·취소·삭제 API를 구현한다.
- [x] 동일 사용자 중복 요청과 자기 자신 요청을 차단한다.
- [x] `/friends`에 친구, 받은 요청, 보낸 요청을 구분해 표시한다.
- [x] 친구 카드에서 프로필과 해당 친구의 허용된 기록으로 이동할 수 있게 한다.
- [x] 비어 있는 목록에는 초대 또는 친구 찾기 CTA를 제공한다.
- [ ] 요청 상태 변화가 알림과 친구 피드 권한에 즉시 반영되게 한다.

**완료 조건**

- [x] 수락된 양방향 관계만 `FRIENDS` 공개 범위에 포함된다.
- [ ] 요청·수락·삭제 후 양쪽 사용자 화면의 관계 상태가 일치한다.

### P1-06. 친구 전용 피드 + 공개 대상 선택

목표 경로: 기존 `/community`를 `/feed`로 재편하거나 탭 라벨을 `친구 피드`로 변경

사용자 플로우:

`친구 피드 → 허용된 기록 읽기 → 스포일러 열기 → 댓글·이모지 반응 → 알림에서 복귀`

- [x] 공개 전체의 `추천`, `인기`, `최신` 탭을 MVP에서 숨기거나 후순위 기능으로 분리한다.
- [x] 수락된 친구의 `FRIENDS` 기록과 나에게 지정된 `SELECTED` 기록만 피드에 포함한다.
- [x] 기존 커뮤니티 카드, 스포일러, 댓글 UI를 재사용한다.
- [x] 좋아요를 유지할지 소규모 이모지 반응으로 바꿀지 결정한다.
- [ ] 댓글·반응 권한을 기록 조회 권한과 동일하게 검증한다.
- [ ] 친구 관계 해제 또는 공개 범위 변경 시 피드·상세 접근 권한을 즉시 회수한다.
- [ ] 알림 항목에서 대상 기록·댓글로 이동하는 deep link를 추가한다.
- [x] 피드가 비었을 때 공개 게시물을 추천하지 않고 친구 초대·첫 기록 CTA를 제공한다.

**완료 조건**

- [ ] 친구가 아닌 사용자는 `FRIENDS` 기록을 피드와 직접 URL 모두에서 볼 수 없다.
- [ ] 공개 범위 변경과 친구 관계 변경이 캐시된 피드에도 즉시 반영된다.
- [x] 오류 상태와 빈 피드 상태가 동시에 노출되지 않는다.
